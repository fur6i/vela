# Security implementation and limits

This is an experimental Electron browser shell, not an independently audited browser distribution. The changes harden the shell; they do not modify Chromium's C++ engine or establish parity with Chrome/Safari's security services.

## Applied controls

- Global sandbox enabled; remote pages have no Node integration or app-control IPC bridge. The isolated preload performs ad blocking and accepts volume programs only from the main process; it exposes no page API. Context isolation, web security, background throttling, no webviews, and no insecure active content opt-in remain enabled. Chromium site-per-process isolation is requested. No certificate-error bypass is installed.
- Application IPC accepts only the local UI's main frame. Commands use fixed operations; download actions only operate on known download IDs, and “show in folder” never executes a downloaded file. The UI uses a strict local CSP, local fonts/assets, text nodes for page titles, and no remote JavaScript or favicon services.
- URLs use parsed HTTP(S) validation. Embedded credentials, privileged protocols, external application handlers, and automatic JavaScript popup windows are rejected. Public HTTP addresses are upgraded by default; localhost is exempt. There is no automatic HTTP fallback after an HTTPS failure.
- Camera/microphone, location and notification requests require the active page, HTTPS, a main-frame request matching the current origin, and explicit consent. Grants are scoped to that page and revoked on navigation. Other device permissions, screen sharing, and third-party frame permission requests are denied. Native OS permission requirements still apply.
- Network and cosmetic ad/tracker filtering use Ghostery. Cold offline startup has a small emergency list until full subscriptions are available. Filter update failures retain the previous engine. Filter files and the profile use temporary files followed by atomic rename.
- Version 0.3 selects scriptlets synchronously at document start and runs each in a separate function in the page's main world through Electron's context bridge. All functions share one pristine built-in snapshot, preventing wrappers from repeatedly wrapping one another. The page's CSP is not disabled. Cosmetic IPC accepts only the browsing session's real main frame and matching origin; DOM feature batches are bounded and cannot request arbitrary code. Downloaded filter resources are trusted inputs executed in the page world, without Node privileges. Cosmetic mutation updates request styles only, never reinjecting scriptlets late. Quick fixes come directly from the official uBlock Origin subscription, with a versioned cache to avoid reusing the previous stale snapshot.
- Packaged binaries disable RunAsNode, NODE_OPTIONS and main-process inspector switches. Cookie encryption, embedded ASAR integrity checks, and loading only from the app archive are enabled through Electron fuses. Development runs do not receive the packaging fuses.
- Private windows use an in-memory site session and a separate temporary runtime profile. Normal history and profiles are not saved from those windows. The temporary profile is removed on a best-effort basis after a normal exit.

## Material limits

VirusTotal accepts only explicitly selected, pasted or downloaded local files. It hashes file contents locally, searches reports by SHA-256, and never executes the file. Upload requires a per-file native confirmation that explains public sharing. API credentials stay in the main process, are encrypted using safeStorage when available, and are never included in UI snapshots or profile JSON. API requests use fixed HTTPS VirusTotal hosts and reject redirects, with bounded files, timeouts, cancellation and quota handling. File hashes are rechecked before upload and report refresh. Tests use harmless fixtures and a mocked VirusTotal API; live API scans require the user's own key and have not been claimed as verified.

Panic shortcuts are scoped to Vela's focused window. Configuration accepts only HTTP(S) destinations without credentials and avoids reserved browser/OS combinations. Triggering hides and mutes the old page immediately and replaces the active navigation. It does not erase browsing history, close other tabs, remove files or provide forensic privacy. Download popups reuse the isolated dock surface, with the underlying website left visible.

Privacy protection has its own cached EasyPrivacy engine and offline tracker filters. Site exceptions control tracking filters, third-party Cookie/Set-Cookie stripping and GPC/DNT signals. Consent automation runs in an isolated frame world, scans only cookie/consent containers, clicks only explicit rejection labels, bounds work and attempts, and stops observing after a deadline. It never auto-accepts consent or dismisses a banner without a rejection action. IPC validates the actual owned browsing frame and URL. This is heuristic consent handling, not universal tracking prevention; GPC/DNT depend on site cooperation. The extensions dock uses a separate transparent WebContentsView without hiding or resizing the active site; external extension popups use the same in-window model.

Native video tools fetch official yt-dlp, FFmpeg and Deno release assets over HTTPS, verify publisher SHA-256 manifests before execution, and extract only fixed executable names. They run with argument arrays, without a shell, user yt-dlp config, third-party plugins or browser account cookies. Video output is staged in a unique directory beside the user-selected destination; temporary paths are checked before cleanup. Installed tools can be updated explicitly. These native helpers run with the user's OS privileges and remain a separate trusted dependency boundary.

Native volume runs in an isolated JavaScript world and does not expose a website-to-app bridge. Image conversion decodes bytes into canvas without disabling the site's CSP. Full-page capture attaches an in-process Chromium debugging session only for the capture and detaches afterwards; no remote debugging port is opened. User-added unpacked extensions require a permission summary and explicit installation action; their Chrome API compatibility is partial, they can read pages according to their manifest, and they are excluded from private sessions.

Installed NSIS builds use electron-updater with GitHub releases, automatic downloads and an explicit restart action. Development, smoke, private and portable runs disable it. There is no code-signing certificate, Safe Browsing integration, password manager, or independent third-party security audit. Keep Electron and the dependencies updated and rebuild/distribute promptly. Do not interpret the ad blocker as comprehensive malware protection. Private browsing does not provide anonymity, and downloaded files survive private-window closure. Windows processes with equivalent or higher privileges remain outside this application's security boundary.

Tests cover URL and permission-origin validation, remote Node/IPC isolation, blocked ad scripts, blocked privileged/spoofed navigation, private-session persistence policy, lazy tab allocation, suspension/resume, UI update batching, and basic feature flows. Tests are not a penetration test. Native permission dialogs, printer drivers, every website/OAuth flow, and all download formats have not been exhaustively exercised.


References: [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), [Electron fuses](https://www.electronjs.org/docs/latest/tutorial/fuses), [session permissions](https://www.electronjs.org/docs/latest/api/session), [Ghostery Adblocker](https://github.com/ghostery/adblocker).

0.10.0 routes filter downloads and the VirusTotal transport through [Chromium networking](https://www.electronjs.org/docs/latest/api/net), removing the Node/Undici HTTP-parser path from those requests. Private windows run independently of the normal instance lock, use an in-memory browsing session and a unique temporary UI profile, and do not load normal browsing history or extensions. Private shutdown first attempts direct deletion. Only Windows lock errors launch a minimal hidden PowerShell helper to wait for the parent and retry deletion of the verified temporary child. Normal startup asynchronously removes marked orphan profiles whose owning process is no longer alive; live and unmarked profiles are preserved conservatively. No Electron cleanup process is launched. External owner markers allow cleanup after crash or late runtime cache recreation. Tests cover private windows, cookie isolation, no profile persistence and subsequent orphan removal.

## Release 0.11.0 boundaries

Raster favicons are decoded in the main process using nativeImage and a bounded ICO-to-PNG decoder (maximum 256 px per ICO frame and 256 KiB per response). PNG/JPEG dimensions are checked before native decoding (maximum 1024 px per side), preventing oversized raster headers from reaching the decoder. Unsupported SVG formats are skipped; remote SVG is never rasterized inside the privileged UI. Site-icon requests omit credentials and use a bounded cache with at most three concurrent transfers. Favorites retain the normalized PNG icons in the user profile. The strict CSP, sandbox, trusted-main-frame IPC checks, WebContentsView and packaging fuses remain enabled.

Store downloads use Chromium networking without credentials, a 50 MiB cap and timeouts, allowlisted HTTPS redirects, developer-signature/ID verification for CRX2/CRX3, bounded ZIP extraction rejecting traversal, symlinks, Windows aliases and duplicate paths, and a bounded manifest. A native permission confirmation precedes loading with file access disabled. Installed extensions remain trusted third-party code with access granted by their manifests; this is not a malware scan or complete Chromium extension implementation. Store-managed directories are separate from user-selected folders.

Media Downloader URLs require public HTTPS without credentials. DNS answers must all be public; the local CONNECT proxy pins each connection to a validated public address, including redirects and extractor subrequests using that proxy. HTTP requests through the proxy are rejected. Helpers receive fixed argument arrays and an explicit -- separator; official downloads use Chromium networking and SHA-256 verification. Helpers are not OS-sandboxed: the checks reduce SSRF exposure but cannot guarantee isolation against a compromised helper or extractor ignoring its proxy. They are not bundled or licensed as Vela MIT code.

Unsigned updates trust the fixed GitHub release provider (fur6i/vela), HTTPS and updater checksums. With no publisher certificate these checks do not authenticate an independent software publisher: protecting the GitHub account, workflow permissions and release assets is essential. No publisherName is configured. The updater never installs on ordinary app exit; only the explicit restart command installs a downloaded update. End-to-end delivery requires an actual published release and is not established by local unit tests.

Report security issues privately using the repository security advisory feature at https://github.com/fur6i/vela/security/advisories/new. Do not include credentials or personal browsing profiles in public issues.

## Interface language

Italian/English translations are bundled local data. The shared translator interpolates parameters as literal text; the UI updates text nodes and known attributes without innerHTML, dynamic script loading or external translation services. The language IPC accepts only the centralized supported-language list and retains the existing trusted-main-frame gate. The installer hint is accepted only from a regular, non-symlink file of at most 16 bytes containing a supported code; the saved profile setting takes priority. Installer customization writes only the language hint and does not edit or remove the browsing profile. Native Windows file-dialog internals follow Windows language settings.
